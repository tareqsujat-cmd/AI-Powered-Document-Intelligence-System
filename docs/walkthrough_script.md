# Walkthrough script

A script for recording a walkthrough of about ten minutes. The files come from `eval/dataset/`, generated by `python eval/generate_dataset.py`, and a few are copied into `sample_data/`.

## Before recording

1. `docker compose up --build`, with `LLM_API_KEY` set in `.env`.
2. Wait until http://localhost:8000/health/ready reports `ok`, then give the worker a minute to load the embedding model.
3. Open http://localhost:3000. Start from an empty database, so that duplicate checks only find what you upload.

## 1. The problem and the design (1 minute)

- One sentence on the problem: invoices arrive as PDFs, scans, photos and spreadsheets, and someone keys them in and checks the sums by hand.
- Show the architecture diagram in [architecture.md](architecture.md): FastAPI, Celery workers with Redis, PostgreSQL with pgvector, Tesseract OCR, an LLM for extraction, Next.js.
- The key rule: the system never invents a value. Anything it cannot see is null, with a reason.

## 2. Upload several formats at once (2 minutes)

Drop these on the upload area together:

| File | What it shows |
|---|---|
| `digital_pdf/digital-01-classic.pdf` | A digital PDF, read from its text layer |
| `scanned_pdf/scan-02.pdf` | A scan, read with OCR |
| `image/photo-02.jpg` | A photo of an invoice |
| `spreadsheet/two-sheets.xlsx` | A workbook with one invoice per sheet |
| `digital_pdf/batch-4-invoices.pdf` | Four invoices in one PDF, split apart |
| `corrupted/password.pdf` | A file that must fail with a clear reason |

Point out the per-file upload progress, then the dashboard: live status per stage, the counters, and the filters.

## 3. Inspect a result (2 minutes)

Open `scan-02.pdf`:

- The page preview beside the extracted fields.
- The confidence of each field, and the source snippet it came from.
- The line items.
- The processing history: each stage with its timing.

Open `batch-4-invoices.pdf` to show four invoices found in one file.

Open `password.pdf` to show the failure reason and the retry button.

## 4. Validation and review (2 minutes)

Upload `seeded_error/wrong-total.pdf`, `seeded_error/no-total.pdf`, and then `seeded_error/match-original.pdf` followed by `seeded_error/mismatch-copy.xlsx`.

- `wrong-total.pdf`: subtotal plus tax does not equal the total, so it needs review.
- `no-total.pdf`: no total is printed, so the total is null with a reason. It is not calculated.
- `mismatch-copy.xlsx`: the spreadsheet disagrees with the PDF on the total, a PDF-vs-Excel cross check.

Correct a field inline, and show that the validation reruns and the change appears in the history with its before and after values. Resolve an issue, and show the document leaving the review queue. Click reprocess on one document.

## 5. Search (1 minute)

On the search page:

- Keyword: an invoice number from one of the uploads.
- Semantic: "shipping and transport costs", which shares no words with the invoices it finds.
- Hybrid: the same query, combining both.

## 6. API, tests and evaluation (2 minutes)

- http://localhost:8000/docs: upload, status, results, corrections, reprocess, reprocess-failed, search, metrics.
- The test suites: `pytest backend/tests -q` and `npm test` in `frontend`. See [test_coverage.md](test_coverage.md).
- [eval/report.md](../eval/report.md): accuracy, line-item accuracy, validation precision and recall, processing time, and success and failure rates, all measured on 50 labeled documents. Mention one thing it does well and one it does not, from the report.
- [ai_disclosure.md](ai_disclosure.md) and [/prompts](../prompts).
